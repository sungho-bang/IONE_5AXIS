- 읽기 전용 참조: D:\Works_Updates\대주이엔지\Git_IONE_4AXIS
- 요청: X1135 I-Mark를 4축 신규 FRONT 그리퍼 시퀀스와 같은 역할로 적용하고, REAR BandRollerServo는 추가 전 기능으로 복원.
- 실제 설비 실행, 모터 구동, 실린더 출력, 센서 강제 입력은 하지 않았습니다.

## 1. 핵심 결과

| 항목 | 수정 전 5축 | 수정 후 5축 |
|---|---|---|
| X1135 I-Mark 제어 대상 | REAR BandRollerServo | FRONT TapeLoadingServo |
| 제어 축 번호 | AxisNo=4 | AxisNo=1 |
| 센서 객체 | RearLoadingUnit.IMarkCheckSensor | FrontLoadingUnit.FrontIMarkCheckSensor |
| 감지 후 동작 | 롤러 보정, 수량 처리, 좌표 초기화 | 그리퍼 보정 완료 후 고정/이송 그리퍼 인계 |
| 신규 사용 설정 | 기존 REAR UseIMark와 혼용 | 별도 UseFrontIMark |
| 신규 Offset | IMarkSensorOffset | FrontIMarkSensorOffset |
| REAR 마크 감지 | 신규 X1135 처리 | 원래 BlackMarkCheckSensor X1140 |

FRONT/REAR 모터의 AxisNo 값 자체를 바꾼 것이 아닙니다. X1135를 사용하는 시퀀스의 소속과 대상 모터를 바로잡았습니다.

## 2. FRONT 정상 시퀀스

1. 기존 순서대로 TapeLoadGrip 잡기, TapeHoldGrip 풀기를 수행합니다.
2. 사용 여부, 센서 상태, 그리퍼 상태, 시간과 위치 설정을 확인합니다.
3. 고속 목표 = max(0, FeedingPitch - FrontIMarkSlowDistance)까지 이동 완료를 기다립니다.
4. 저속 목표 = FeedingPitch입니다. 센서 OFF이면 저속 탐색을 한 번 지령한 뒤 X1135 ON을 기다립니다.
5. 새 ON에서 ActualPos를 감지 위치로 기록하고 정지 명령을 보냅니다.
6. Stop.Sequence로 정지 완료를 확인합니다.
7. 보정 목표 = 감지 위치 + FrontIMarkSensorOffset입니다. 0이면 추가 이동을 생략합니다.
8. 보정 이동 완료 뒤 TapeHoldGrip 잡기 완료, TapeLoadGrip 풀기 완료 순서로 진행합니다.
9. 기존 후속 복귀 단계에서 HomePos로 이동하고 TapeLoadGrip 잡기, TapeHoldGrip 풀기를 수행합니다.

4축처럼 이미 처리한 ON이 계속 유지되면, 고속 접근 이후 중복 저속 탐색과 Offset를 생략합니다. OFF를 관측하면 다음 ON을 다시 받을 수 있습니다. 초기화 완료 당시 ON인 마크는 이미 처리된 것으로 기억합니다.

FRONT 사용을 끄면 기존 원단 피치 위치 이동과 실린더 순서로 동작합니다. 고속 접근을 위해 줄인 거리값이 미사용 모드에 남지 않도록 원단 피치를 다시 적용합니다.

자동 이송의 5축 옵션 프레스 분기, 원단 1피치, 전체 1회 운전 등을 포함한 전진 이송 호출 10곳을 공통 TapeLoadingMoveWithIMark로 연결했습니다. 기존 5축 프레스/이재기 병행 동작과 실린더 IO는 유지했습니다.

### 4축 소스의 문제를 그대로 복사하지 않은 부분

- 4축 참조의 저속 지령 단계에 다음 단계 전환이 누락된 부분은 복제하지 않았습니다. 저속 지령 후 감지/시간 초과 대기로 명확히 전환합니다.
- Unknown/미연결 입력을 ON으로 해석하지 않습니다.
- 보정 전 정지 완료를 기다립니다.
- 보정 목표의 위치 한계와 감속 후 목표 초과를 확인합니다.
- 탐색 시간 초과나 비정상 중단 후에는 초기화가 필요하며 자동 재탐색하지 않습니다.
- 정상 일시정지/재개는 진행 단계와 보정 목표를 유지합니다. 탐색 재개 시 지령을 한 번 다시 보냅니다.
- 원단 사용 길이는 I-Mark 사용 중 실제 완료된 전진 거리로 집계합니다. 고속 구간이 짧아졌다는 이유로 저속/보정 구간이 사용 길이에서 빠지지 않게 했습니다.

## 3. REAR 복원 범위

복원 기준은 Git 커밋 a3ad897의 FARearLoadingModule.cs입니다. 파일 끝 개행을 제외한 내용이 기준 버전과 동일함을 정적 검사로 확인했습니다.

- MovingRoller: 기존 X1140 감지, 기존 재시도, 카운터 증가, 좌표 초기화, 지연 처리 복원.
- ManualWorkLoading: 기존 마크 사용/미사용 분기 및 수동 피딩 복원.
- WorkManualLoading: 기존 단계 운전 및 연속 운전 복원.
- SearchingImark: 기존 X1140 마크 찾기 복원.
- Initialize: 원본 초기화 분기와 롤러/커터 처리 복원.
- 신규 X1135 센서 속성과 신규 Offset 처리, FRONT 방식 복구 플래그는 REAR에서 제거.

기존 REAR UseIMark 설정과 JOB의 REAR 거리값은 보존했습니다. 기존 기능에 BlackMark 감지가 있으므로 “원복”은 REAR의 모든 마크 기능 삭제를 뜻하지 않습니다.

주의: 원본 REAR의 수동 탐색/연속 운전에는 기존 반복 탐색 조건이 남아 있습니다. 신규 FRONT의 시간 초과/초기화 규칙을 REAR에 다시 적용하지 않았습니다. REAR 실기 동작은 별도 확인이 필요합니다.

메인 사용 선택은 설비 정지, 선택 JOB 적용 완료, 관련 시퀀스/모터/그리퍼 비동작 조건에서 가능합니다. 미적용 JOB이나 FRONT 거리/Offset 변경이 아직 적용되지 않은 상태에서는 초기화로 JOB을 적용하라는 안내를 표시합니다.

메인 선택은 현재 FRONT 상태와 선택 JOB의 사용 여부를 맞추며, REAR UseIMark에는 쓰지 않습니다. 디스크 저장은 기존 설정 화면의 저장 버튼을 사용합니다. JOB 거리/보정 변경 역시 저장 후 해당 JOB을 초기화로 적용해야 합니다.

기존 jobfile.xml의 사용자 편집 내용은 변경하지 않았습니다. 새 FRONT 항목이 아직 없는 JOB은 코드 기본값으로 로드되며 다음 JOB 저장 때 새 항목이 기록됩니다. 이전 IMarkSensorOffset 값은 FRONT Offset로 복사하지 않습니다. 기존 XML에 남아 있는 이전 필드는 새 FRONT 동작에 사용하지 않습니다.

## 9. 적용 전 확인

1. 새 실행 파일과 수정한 FRONT/REAR PartList.xml, ModuleParameters.xml이 같은 실행 폴더에 있는지 확인합니다.
2. 해당 JOB에서 FRONT 사용, 원단 피치, 저속 탐색 거리, Offset를 확인하고 저장합니다.
3. 안전한 상태에서 해당 JOB을 초기화로 적용합니다. 메인의 FRONT 선택은 적용된 JOB 기준입니다.
4. 자격 있는 담당자가 실제 X1135 극성, 센서 설치 위치, 파지 상태, 정지거리, Offset 방향/범위, 감지 실패 정지를 저속 시운전으로 확인해야 합니다.
5. REAR는 별도 X1140 기능입니다. 필요한 REAR BlackMark 사용 여부와 기존 포장 동작을 독립적으로 확인합니다.

모의 시험 통과는 실기 안전 검증이나 센서 응답시간 보증을 의미하지 않습니다.
