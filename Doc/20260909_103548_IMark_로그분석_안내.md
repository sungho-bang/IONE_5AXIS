# I-Mark 보정 시퀀스 로그 분석 안내

작성일: 2026-09-09

## 1. 저장 위치

실제 운전 로그는 실행 파일 위치 아래에 저장됩니다. 장비 이름이 VT3500인 기본 Debug 실행 예시는 다음과 같습니다.

```text
폴더: D:\Works_Updates\대주이엔지\Git_IONE_5AXIS\FAFramework\bin\Debug\Log\VT3500\IMarkLog\2026\09
파일: 2026-09-09.log
```

날짜에 따라 YYYY/MM/YYYY-MM-DD.log로 바뀝니다. TraceLog 비활성화 상태에서도 전용 IMarkLog는 기록됩니다.
로그 보관 설정은 실행 폴더의 config/log_setting.cfg이며 IMarkLog 기본값 7일은 그대로입니다.
이번에 만든 Doc의 모의 로그는 테스트 기록이며 실제 설비 운전 기록이 아닙니다.

## 2. 한 번의 피딩 식별

- Flow=Rear4AxisStyleV1: 이번에 적용한 4축형 흐름.
- Schema=IMarkV2: 기존 키-값 상세 로그 형식 유지.
- RunId: 시퀀스 Start마다 생성하는 ID.
- Seq / Caller: 시퀀스와 호출자.
- Step / StepName / Action: 현재 단계.
- ElapsedMs: 해당 시퀀스 실행 이후 경과 시간.
- POSITIONING_BEGIN: 해당 피딩에 고정한 AppliedOffset과 TimeoutMs.

수동 연속은 하나의 RunId 안에서 여러 번 피딩할 수 있습니다.
그 경우 CONTINUOUS_FEED_BEGIN 또는 POSITIONING_BEGIN부터 POSITIONING_COMPLETED까지를 한 회차로 나눕니다.

## 3. 정상 이벤트

| 이벤트 | 의미 |
|---|---|
| START | 시퀀스 시작. IO, 축, 빠른/느린 위치·속도·시간 등 구성 기록 |
| MODE_SELECTED | 자동, 수동, 초기화 등 분기 |
| POSITIONING_BEGIN | 빠른 이동 여부, 실제 적용 보정값, 제한시간 |
| SLOW_SEARCH_COMMAND | 저속 탐색 1회 지령 |
| INPUT_CHANGED | 폴링 시 관찰한 입력 변화 |
| IMARK_REARMED | OFF 관찰로 다음 ON 처리를 다시 허용 |
| DETECTED_STOP_REQUESTED | 명시적인 ON 감지, Stop 요청, DetectedPos/AppliedOffset/Target |
| STOP_CONFIRMED | 정지 시퀀스 완료 |
| OFFSET_SKIPPED | 보정값 0으로 추가 이동 생략 |
| OFFSET_MOVE_PREPARED | 감지 위치, 적용값, 목표, 저속 속도·가감속 |
| OFFSET_MOVE_COMPLETED | 위치 이동 시퀀스 완료와 실제 위치 |
| SAME_ON_SKIPPED | 처리한 ON 유지로 저속 탐색 및 보정 생략 |
| POSITIONING_COMPLETED | 공통 I-Mark 처리 완료 |
| FEED_COUNTED_STOP_REQUESTED | 자동/1사이클 카운트 반영 |
| MANUAL_FEED_COUNTED | 수동 피딩 횟수 반영 |
| INITIAL_POSITION_ESTABLISHED | 초기화의 마크 기준 확립 및 복구 상태 해제 |
| TERMINATED | 시퀀스 정상 종료 |

매 스냅샷에는 X1135의 입력 이름/인덱스/원시값/반전 정보, ActualPos, CommandPos, ServoOn,
RunFlag, MotionDone, ServoAlarm, 카운트, 현재 JOB, 빠른/느린/보정 이동 상태와 오류가 들어갑니다.
Offset은 모듈의 현재 설정값이고 AppliedOffset은 해당 피딩 시작 시 고정한 값입니다.
OffsetTarget은 공유 모터의 TargetPosition 스냅샷이므로 실제 보정 목표는 OFFSET_MOVE_PREPARED의 Target도 함께 확인합니다.

## 4. 정지 및 오류

| 이벤트 / 이유 | 확인 사항 |
|---|---|
| POSITIONING_SUSPEND_STOP_REQUESTED | 일시정지 요청 시 롤러 Stop 지령 |
| SLOW_SEARCH_RESUMED | 명시적 재개 후 중단된 저속 탐색을 한 번 재지령 |
| POSITIONING_ABORT_STOP_REQUESTED | 강제 중단. RecoveryRequired=true, 초기화 필요 |
| POSITIONING_FAULT_STOP_REQUESTED | 공통 I-Mark 오류 감지 및 Stop 지령 |
| POSITIONING_ALARM | 기존 I-Mark 알람 번호와 구체적인 Reason |
| SearchTimeout | 설정 탐색 시간 안에 ON을 확인하지 못함 |
| InvalidOrMissingInput | 센서 미연결, 입력 구성 없음 또는 Unknown |
| InvalidPositioningConfiguration | 위치 객체, 보정값 또는 제한시간 설정 오류 |
| InvalidOffsetTarget | 계산한 목표가 NaN/Infinity |
| OffsetTargetOutsidePositionLimits | 기존 저속 위치의 LwLimit/UpLimit 범위를 벗어남 |
| StopOverrunBeyondOffsetTarget | 정지 실제 위치가 계산 목표를 모터 허용오차보다 초과 |
| InitializeRequiredAfterInterruptedPositioning | 이전 중단/오류 때문에 초기화가 필요함 |
| OffsetMoveError / SeqState | 기존 모터 이동 시퀀스의 실패 및 중단 상태 확인 |

POSITIONING_ALARM 이후에는 자동 재탐색하지 않으며 카운트나 후속 컷팅 단계로 진행하지 않습니다.
알람 확인만으로 진행되지 않습니다. 원인 조치 후 초기화로 마크 기준을 다시 세워야 합니다.
정상 Suspend/Resume는 강제 중단과 구분되며, 보정 중에는 이미 계산한 목표가 유지됩니다.

## 5. 로그를 전달할 때

1. 문제가 발생한 날짜·시간, 선택 JOB, 자동/수동/찾기/초기화 중 어느 동작인지 알려주세요.
2. 해당 날짜 IMarkLog 전체 파일과 같은 시간의 AlarmLog를 함께 전달하면 좋습니다.
3. 앞뒤 여러 회차를 포함해야 '계속 ON인지', 'OFF가 관찰됐는지', '어느 보정값이 실제 적용됐는지'를 비교할 수 있습니다.
4. UI 보정값, X1135 신호 화면, 모터 현재 위치 화면도 있으면 원인 판별에 도움이 됩니다.
5. 로그에 OFFSET_MOVE_PREPARED는 있지만 OFFSET_MOVE_COMPLETED가 없다면 정지/이동 상태, 오류, 외부 중단을 먼저 확인합니다.

현재 로그만으로도 소프트웨어가 어느 입력을 관찰했고 어떤 위치를 지령했는지, 보정을 생략/완료/중단한 이유를 추적할 수 있습니다.
다만 하드웨어 래치 기록이 아닙니다. 스캔 사이의 짧은 센서 펄스와 실제 물리적 정지 정확도를 입증하려면 장치 측 계측이 필요합니다.
비동기 저장 큐가 있으므로 프로세스 강제 종료, 디스크/권한 오류에서 모든 마지막 로그의 보존을 보장하지 않습니다.
쓰기 실패는 SystemLog를 함께 확인하세요.
