# FRONT I-Mark 레시피 즉시 적용 수정 보고서

- 작업일: 2026-09-10
- 작업 식별자: `20260910_110342`
- 대상: `D:\Works_Updates\대주이엔지\Git_IONE_5AXIS`
- 요청: JOB에서 I-Mark를 설정한 뒤 메인 RECIPE를 선택하면 초기화 없이 바로 적용.
- 이 보고서는 이전 보고서의 **메인 I-Mark 변경을 위해 초기화가 필요하다는 UI 적용 조건**을 대체한다. 실제 설비의 원점 설정, 안전 인터록 및 위치 결정 실패 후 복구 조건은 대체하지 않는다.

## 1. 변경 전 원인

메인 RECIPE 선택 이벤트는 `MainLoopModule.SelectJob`에 이름만 넣었다. I-Mark 사용 선택은 `LoadedJobName`이 선택 레시피와 같고 FRONT 설정이 운전값과 일치해야 활성화되었다. `LoadedJobName`은 기존 초기화의 `LoadJob`에서 설정되므로 레시피만 선택했을 때 버튼이 비활성이었다.

## 2. 변경된 사용 순서

1. `설정 > JOB 설정`에서 `10x15`를 선택한다.
2. FRONT I-Mark 사용 여부, 탐색 거리, 설치 보정(오프셋), 원단 피치와 속도를 설정하고 저장한다.
3. 설비가 정지하고 진행 중이거나 일시정지된 관련 동작이 없는 상태에서 메인 RECIPE의 `10x15`를 선택한다.
4. 선택 이벤트에서 FRONT 설정이 즉시 반영되고 메인 `FRONT I-Mark`에 실제 사용/미사용이 표시된다. 이 설정 적용 자체에는 초기화가 필요 없다.
5. 이미 메인에 같은 레시피가 선택되어 있다면, JOB 수정/저장 후 메인 RECIPE 오른쪽의 원형 화살표 적용 버튼을 누른다. 다른 레시피를 선택했다 돌아올 필요가 없다.

메인의 사용/미사용을 직접 변경하는 기능도 유지된다. 메인에서 변경한 사용 여부는 운전값과 선택 JOB에 반영되며, 재실행 후 보존하려면 기존 설정 저장 기능을 사용해야 한다. 레시피 적용 버튼은 다른 미저장 설정까지 디스크에 저장하지 않는다.

## 3. 즉시 적용 범위

| JOB 항목 | 적용 대상 | 결과 |
|---|---|---|
| `UseFrontIMark` | `FrontModule.UseFrontIMark` | 사용/미사용 반영 |
| `FeedingPitch` | FRONT 빠른 이동/느린 이동 위치 | 사용이면 빠른 목표 `max(0, 피치 - 탐색 거리)`, 느린 목표 `피치` |
| `FeedingSpeed` | `TapeLoadingServo.TapeLoadingPos.DriveSpeed` | 기존 형식인 정수 속도로 변환하여 반영 |
| `FrontIMarkSlowDistance` | 빠른 이동 목표 계산 및 운전 JOB | I-Mark 탐색 구간 반영 |
| `FrontIMarkSensorOffset` | `FrontModule.FrontIMarkSensorOffset` | 검출 후 오프셋 반영 |

미사용 레시피를 적용하면 FRONT 빠른 이동 목표는 전체 원단 피치로 돌아간다. FRONT 느린 이동 속도, 가감속 및 모터 스케일은 이번 레시피 적용 기능이 변경하지 않는다.

`MainLoopModule.MoveJobInfo`에도 위 다섯 항목만 동기화한다. 다른 프레스/포장 JOB 항목, REAR `UseIMark`, `BandRollerServo`, 프레스 모터 설정은 이번 즉시 적용 대상이 아니다. 전체 JOB의 나머지 항목을 적용하는 기존 초기화/LoadJob 경로는 유지된다. `LoadedJobName`이나 `IsInitializedOk`를 강제로 설정하지 않는다.

## 4. 적용 흐름과 보호 조건

```text
RECIPE 선택 변경 또는 RECIPE 옆 적용 버튼
  -> 선택 JOB이 현재 JOB 목록에 존재하는지 확인
  -> 설비 정지 상태 확인
  -> FRONT 모터 운전 피드백 및 관련 시퀀스 실행/일시정지 여부 확인
  -> FRONT 다섯 설정값을 별도 객체로 읽고 검증
  -> FRONT 이동 설정과 사용 여부 반영
  -> 운전 JOB의 FRONT 다섯 항목과 선택 레시피 이름 동기화
  -> IMarkLog에 적용 기록
  -> 메인 FRONT I-Mark 표시/활성 상태 갱신
```

- 이 경로에서 모터 이동, 원점 이동, 초기화 또는 실린더 명령을 실행하지 않는다.
- 자동 운전, 초기화 상태 및 관련 수동/일시정지 시퀀스가 남아 있으면 적용을 거부한다. 나중에 자동으로 재적용하는 예약 동작은 없다.
- 선택 변경이 거부되면 기존 레시피 선택으로 되돌리고 이유를 표시한다. 동일 레시피 재적용 실패 시에도 기존 운전 설정을 유지한다.
- 음수/비유한 오프셋과 거리, 잘못된 피치/속도, I-Mark 이동 한계 및 느린 속도 조건을 검증한다. I-Mark 사용 시 정수 변환 결과 속도가 0이 되는 값도 거부한다.
- 오프셋 오류가 다른 이동 설정을 부분적으로 변경한 뒤 발생하지 않도록 적용 전에 검사한다.
- 기존 I-Mark 검출 ON 처리 기억과 위치 결정 실패 후 복구 필요 상태를 유지한다. 이 버튼은 오류 복구용 초기화를 대신하지 않는다.
- 안전 도어/Area Sensor 무시 설정, 축 번호, IO 주소, 센서 극성은 변경하지 않았다.

```text

```


| 이벤트 | 의미 |
|---|---|
| `RECIPE_FRONT_IMARK_APPLIED` | 메인 레시피의 FRONT 설정 적용 성공 |
| `RECIPE_FRONT_IMARK_REJECTED` | 선택/재적용 거부, `Reason` 확인 |

이번 테스트에서 생성한 예제는 `20260910_110342_IMark_Recipe_모의로그.log`로 보관했다. 테스트용 설비 이름과 모의 값이며 현장 기록이 아니다. IMarkLog 보관 기본값 7일은 변경하지 않았다.
