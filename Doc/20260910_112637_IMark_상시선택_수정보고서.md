# FRONT I-Mark 상시 선택 수정 보고서

- 날짜: 2026-09-10
- 작업 식별자: `20260910_112637`
- 대상: `D:\Works_Updates\대주이엔지\Git_IONE_5AXIS`
- 요청: 메인 I-Mark 사용 여부를 다른 옵션처럼 초기화 중이나 운전 중에도 선택 가능하게 변경.

## 1. 결과

유효한 메인 RECIPE가 선택되어 있으면 초기화, 운전, 일시정지, 알람 상태에서도 FRONT I-Mark 사용/미사용 선택을 받는다. 기존의 '정지 상태에서만 변경 가능' 조건은 사용 여부 선택에서 제거했다.

단, 사용자가 선택하는 값과 실제 이송에 적용된 값을 분리했다. 진행 중인 이동의 목표나 오프셋을 도중에 바꾸지는 않는다.

| 상황 | UI 선택 | 실제 반영 |
|---|---|---|
| 정지 상태이며 관련 동작이 모두 종료됨 | 가능 | 즉시 적용 |
| 초기화 중 | 가능 | 다음 FRONT 이송 시작 전, 또는 초기화 종료 후 정지/대기 상태에서 적용 |
| 자동/수동 이송 중 | 가능 | 현재 이송 완료 후 다음 FRONT 이송 시작 전에 적용 |
| 이송 일시정지 중 | 가능 | 재개하는 이송은 기존 설정 유지, 이후 새 이송 시작 전에 적용 |
| 알람 상태 | 가능 | 기존 알람 및 복구 조건을 유지하며, 다음 허용된 적용 시점까지 대기 |
| RECIPE 미선택 또는 설비 설정 미로딩 | 불가 | 적용할 JOB/모터 정보가 필요 |

이번 변경은 I-Mark 사용 여부 선택에 대한 것이다. 다른 레시피로 바꾸거나 RECIPE 오른쪽 아이콘으로 설정을 다시 적용하는 기존 기능의 운전 중 차단은 유지했다.

## 2. 화면과 저장

- 라디오 버튼: 사용자가 마지막으로 요청한 사용/미사용을 표시한다. 대기 요청이 없으면 실제 적용값을 표시한다.
- `사용 적용 대기` / `미사용 적용 대기`: 선택은 접수되었지만 현재 이송에는 아직 반영되지 않은 상태.
- `현재: 사용` / `현재: 미사용`: 실제 FRONT 이송 설정에 적용된 상태.
- `적용 오류`: 적용 전 재검증에 실패한 상태. 툴팁에서 원인을 확인한다.
- 대기 중 툴팁에는 현재 실제 사용 상태와 적용 시점을 표시한다.
- 여러 번 선택하면 마지막 요청이 이전 대기 요청을 대체한다.

선택 JOB의 `UseFrontIMark`는 요청이 접수되면 변경한다. 설정 저장을 누르면 대기 중인 선택값도 `jobfile.xml`에 저장된다. 저장하지 않은 변경을 프로그램 종료 후에도 보존한다고 보장하지 않는다. 대기 요청 객체 자체는 메모리에만 보관한다.

## 3. 적용 방식

```text
메인 사용/미사용 클릭
  -> 선택 JOB과 FRONT 설정 유효성 검증
  -> 사용 여부 + 피치/속도/탐색 거리/오프셋의 일관된 복사본 생성
  -> RequestId를 부여하여 마지막 요청으로 보관
  -> 선택 JOB의 사용 여부 갱신
  -> 정지/대기 상태면 즉시 반영
  -> 진행 중이면 현재 이동 설정은 유지
  -> 다음 TapeLoadingMoveWithIMark 첫 단계에서 모터가 다른 동작 중인지 확인
  -> 설정 재검증 후 반영
  -> 변경된 사용 여부로 I-Mark 이동 또는 일반 피치 이동 분기
```

요청 시점의 FRONT 설정 복사본을 사용하므로 요청 이후 JOB의 숫자값을 수정해도 이미 대기 중인 요청을 몰래 바꾸지 않는다. 새 값으로 적용하려면 사용 여부를 다시 선택하거나 정지 상태에서 RECIPE 적용 기능을 사용한다.

요청 반영 시 `MainLoopModule.MoveJobInfo`의 FRONT 다섯 항목도 함께 동기화한다. 실제 이동 명령은 기존 이송 시퀀스가 수행하며, UI 선택 처리나 정지 중 설정 적용 자체는 모터/실린더 명령을 실행하지 않는다.

## 4. 유지한 보호 조건

- 진행 중인 빠른/느린 이동, 오프셋 이동과 일시정지 후 재개 목표는 변경하지 않는다.
- FRONT 축에 다른 이동 또는 정지 명령이 진행 중이면 새 이송 시작 단계에서 적용을 기다린다. 기존 FRONT I-Mark 시간 설정을 넘기거나 검증에 실패하면 알람 처리하며 새 이송을 시작하지 않는다.
- 위치 결정 중단 후 초기화가 필요한 상태는 사용/미사용 변경으로 해제하지 않는다.
- 센서 ON 처리 기억, 좌표, 생산 카운터 및 원점 완료 상태를 임의로 초기화하지 않는다.
- 초기화가 이미 읽은 이전 설정이 뒤늦게 적용되어도 같은 JOB의 더 최신 사용 요청을 버리지 않는다.
- 다른 JOB을 적용하거나 선택 JOB을 제거하면 이전 JOB의 대기 요청은 취소한다.
- 설정 적용과 요청 관리는 같은 잠금으로 보호한다. UI 표시에서도 대기 값을 한 번 읽어 사용하는 방식으로 처리 중 값이 바뀌는 경우를 고려했다.
- 안전 도어, Area Sensor, 비상정지 및 기존 실린더 조건은 변경하지 않았다.
- REAR 탑 롤러 알람 `2005000`의 원인 검사/해제 조건도 변경하지 않았다. I-Mark 사용 선택으로 해당 알람을 우회하지 않는다.
- FRONT `TapeLoadingServo` 축 1 / `X1135`, REAR `BandRollerServo` 축 4 / 기존 `X1140` 매핑을 유지했다.

```text

```

현재 Debug 실행 파일의 오늘 경로:

```text

```

| 이벤트 | 의미 |
|---|---|
| `MAIN_USAGE_REQUESTED` | 요청 접수. `RequestId`, 이전 요청 `Replaces`, `RequestedUse`, 현재 `AppliedUse`, 피치/속도/탐색 거리/오프셋, 설비 상태 기록 |
| `MAIN_USAGE_REQUEST_APPLIED` | 실제 적용. 동일 `RequestId`로 요청과 연결 |
| `MAIN_USAGE_REQUEST_CANCELLED` | 레시피 변경/삭제 등으로 이전 요청 취소 |
| `MAIN_USAGE_REQUEST_FAILED` | 적용 시점의 검증 실패. 같은 오류를 매 UI 갱신마다 중복 기록하지 않음 |
| `MAIN_USAGE_CHANGE_REJECTED` | 잘못된 JOB 또는 설정으로 요청 자체를 받지 못함 |
| `FRONT_JOB_APPLIED` | 모듈에 반영된 실제 목표와 사용 여부 |

`Boundary=BeforeFrontFeed`는 새 FRONT 이송 시작 전, `StoppedIdle`은 정지/대기 중, `RecipeLoad`는 기존 레시피 적용 과정에서 반영되었음을 뜻한다.

기존 즉시 변경 로그 `MAIN_USAGE_CHANGED` 대신 이번 버전은 요청과 적용을 분리하여 기록한다. 시퀀스의 기존 `CycleId`, `RunId`, 입력 변화, 정지/오프셋/실린더 로그는 유지한다. 보관 기본값 7일도 변경하지 않았다.
