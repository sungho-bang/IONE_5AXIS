## 1. 수정 결과

4축 FRONT의 I-Mark 처리 흐름을 5축 REAR의 기존 모터와 입력에 적용했습니다.
기계 전체를 4축처럼 바꾼 것이 아니라, 빠른 이동 / 저속 탐색 / 감지 정지 / 설치 보정 / 중복 ON 처리 흐름을 맞췄습니다.

| 구분 | 적용 내용 |
|---|---|
| 대상 모터 | 기존 5축 BandRollerServo |
| 모터 설정 | 기존 AxisNo=4 유지. 소프트웨어 설정값이며 배선 모터번호로 재해석하지 않음 |
| I-Mark 입력 | 기존 IMarkCheckSensor, X1135 유지 |
| 입력 반전 / 배선 / 다른 IO | 변경하지 않음 |
| 새 JOB 항목 | IMarkSensorOffset |
| 기본값 | 0 mm. 기존 JOB XML에 항목이 없으면 0으로 로드 |
| 보정 방향 | 감지 시 기록한 ActualPos에 양수 보정값을 더함 |
| 보정 속도 | 5축 TapeLoadingSlowPos의 StartSpeed, DriveSpeed, AccelTime, DecelTime |
| 정상 완료 후 | 5축 고유의 카운트, 롤러 좌표 0, 지연, 기존 후속 공정 유지 |
| 자동 감지 재시도 | 기존 최대 3회 탐색을 제거. 시간 초과 시 정지 및 알람 |

기존 5축 빠른/느린 위치 값과 속도, 축 번호, 센서 번호, 알람 번호, 시간 설정 XML은 덮어쓰지 않았습니다.
4축 X1137이나 그리퍼 축 번호를 복사하지 않았습니다. 4축 소스도 수정하지 않았습니다.

## 2. 변경된 자동 / 1사이클 흐름

1. UseIMark가 false면 기존 5축 빠른 위치 이동과 느린 위치 이동을 실행하고 완료 처리합니다. 보정은 적용하지 않습니다.
2. UseIMark가 true면 입력 상태, 위치 설정, 탐색 시간, 보정값과 복구 필요 상태를 확인합니다.
3. BandRollerServo.MoveTapeLoadingPos.Sequence로 빠른 이동 완료를 기다립니다.
4. 저속 탐색 진입 시 OFF면 처리 이력을 해제하고 저속 이동을 한 번 지령한 뒤 감지 대기로 전환합니다.
5. 새 ON이면 Stop을 요청하고 그 직후 ActualPos를 감지 위치로 기록합니다.
6. 이미 처리한 ON이 계속 유지되면 저속 탐색과 보정을 생략합니다. 빠른 이동과 기존 완료 처리는 유지합니다.
7. Stop.Sequence로 정지 완료를 확인합니다.
8. 보정값이 0이면 추가 이동 없이 완료 처리합니다.
9. 보정값이 양수면 목표를 '감지 위치 + 보정값'으로 계산하고 기존 저속 설정을 TargetPosition에 복사합니다.
10. MoveToPos.Sequence가 목표 이동을 완료할 때까지 기다립니다.
11. CurrentCount를 1 증가하고 UICuttingCount를 2 증가합니다.
12. 기존처럼 롤러 좌표를 0으로 설정하고 TimeRollerDelay만큼 기다린 뒤 부모 공정으로 돌아갑니다.
13. 컷팅 횟수 조건 및 실린더 순서는 기존 5축 부모 시퀀스대로 진행합니다.

예: 감지 시 기록한 위치가 100 mm이고 보정값이 2.5 mm이면 목표는 102.5 mm입니다.
정지 완료 위치에 다시 2.5 mm를 더하는 방식이 아닙니다. 감속 중 이동량도 실제 보정 결과에 영향을 줍니다.
그렇기 때문에 정지 후 실제 위치가 목표를 모터 허용오차보다 초과했다면 역방향 보정을 지령하지 않고 알람으로 처리합니다.
현재 저장된 BandRollerServo.Tolerance는 0.5입니다. 이 값은 변경하지 않았습니다.

## 3. 경로별 적용 범위

| 경로 | 빠른 이동 | 설치 보정 | 감지 실패 처리 |
|---|---|---|---|
| MovingRoller: 자동 / 1사이클 | 기존 빠른 위치 이동 | 사용 시 적용 | 정지 + 알람, 자동 재탐색 없음 |
| ManualWorkLoading: 수동 피딩 | 기존 빠른 위치 이동 | 사용 시 적용 | 정지 + 알람, 기존 무제한 재지령 제거 |
| WorkManualLoading: 수동 연속 | 빠른 이동 후 저속 탐색으로 통일 | 적용 후 컷팅 | 정지 + 알람 |
| SearchingImark: I-Mark 찾기 | 생략 | 감지 후 적용 | 정지 + 알람, 기존 반복 지령 제거 |
| Initialize: 초기화 | 생략 | 미적용. 마크 기준 설정 목적 | 초기화 탐색 시간 초과 시 정지 + 알람 |
| WorkManualLoading: 수동 단계 | 기존 단계 조작 유지 | 미적용 | 기존 동작 유지 |

수동 연속 및 I-Mark 찾기는 원래 별도의 I-Mark 전용 명령이므로 UseIMark 옵션과 무관하게 센서를 사용하는 기존 정책을 유지했습니다.
수동 연속의 기존 속도 운전/즉시 OFF 재지령 방식은 공통 빠른 이동 + 저속 탐색 + 보정 완료 방식으로 변경했습니다.
초기화 완료 당시 ON 상태는 이미 처리한 ON으로 기억합니다. 이후 OFF를 관찰하면 다시 감지를 허용합니다.

## 4. 4축과 의도적으로 다르게 처리한 부분

| 항목 | 적용 이유 |
|---|---|
| 모터 / IO / 실린더 | 5축 하드웨어 연결을 유지해야 하므로 4축 부품을 복사하지 않음 |
| 완료 시 롤러 좌표 0 | 5축 롤러의 다음 절대 위치 피딩을 위한 기존 처리 유지 |
| I-Mark 미사용 시 빠른 + 느린 이동 | 5축 기존 위치 피딩 동작 유지 |
| 저속 탐색 다음 단계 전환 | 4축 참조 코드에서 조건 단계의 NextStep 호출이 빠져 있던 부분은 이식하지 않음 |
| Unknown 입력 | OFF가 아니라는 이유만으로 ON 처리하지 않고, 명시적인 ON만 허용 |
| 정지 완료 대기 | 보정 지령 전에 Stop.Sequence 완료를 확인 |
| 잘못된 보정 목표 | NaN, Infinity, 위치 한계 초과, 목표를 지나친 정지 위치는 정지 + 알람 |
| 오류 / 강제 중단 복구 | 초기화 필요 상태를 기록하여 미완료 보정을 같은 ON 완료로 건너뛰지 못하게 함 |

탐색 제한시간은 현재 XML의 TimeLoadingTimeout=1초, 초기화는 TimeLoadingInitialTimeout=1초를 사용합니다.
느린 위치까지 먼저 도달해도 마크가 없으면 제한시간까지 대기한 후 알람입니다. 좌표를 계속 0으로 만들어 재탐색하지 않습니다.
공통 I-Mark 오류에는 기존 AlarmBlackMarkCheckTimeOut 번호를 사용하고 구체적인 이유를 알람 메시지와 IMarkLog에 기록합니다.
모터 정지/위치 이동 시퀀스 자체에서 발생하는 오류는 기존 모터 알람 체계를 유지합니다.

정상적인 일시정지(Suspend) 후 Resume는 진행 중인 단계를 재개합니다.
저속 탐색 중 멈췄다면 저속 목표로 한 번 재지령하며, 보정 중이라면 원래 계산한 절대 목표를 유지합니다.
보정값을 도중에 바꿔도 이미 시작된 피딩의 보정값은 바뀌지 않습니다.
강제 중단(Stop/Abort)이나 공통 I-Mark 오류 후에는 원인을 조치하고 초기화가 필요합니다.
알람 확인만으로 자동 재탐색하거나 후속 공정으로 넘어가지 않습니다.

## 5. UI 위치와 저장

경로: 설정 → JOB 설정 → 대상 JOB 선택 → 화면 맨 위의 고정 I-Mark 영역

- Rear I-Mark 사용 (X1135): 사용 여부 체크박스.
- I-Mark 설치 보정 (mm): 0 이상의 숫자 입력.
- 보정값 0: 감지 정지 후 추가 이동 없음.
- 보정값 양수: 감지 위치를 기준으로 진행 방향 추가 위치 보정.
- 음수, 숫자가 아닌 문자열, NaN, Infinity: 유효성 오류. 저장을 차단하고 기존 유효한 값을 보존.
- 기존 옵션 영역의 I-Mark 토글은 제거하고 위 고정 영역으로 이동.
- 고정 영역은 스크롤을 내려도 위에 남음. 폭이 좁아지면 줄바꿈.

변경 후 기존 하단 '저장' 버튼으로 저장해야 재실행 후에도 유지됩니다.
운전 모듈에는 기존 JOB 로딩 경로(LoadRecipe / 초기화 시 LoadJob)를 통해 적용됩니다.
설정 화면에서 편집하는 JOB과 메인에서 선택한 운전 JOB이 같은지 확인해야 합니다.
UI 편집 즉시 운전 중인 모터에 새 값을 보내는 방식으로 만들지 않았습니다.

실행 파일 기준 저장 위치:

```text
D:\Works_Updates\대주이엔지\Git_IONE_5AXIS\FAFramework\bin\Debug\config\VT3500\jobfile.xml
```

저장되는 항목은 해당 JOB의 MoveJobInfo 아래에 다음과 같이 추가됩니다.

```xml
<IMarkSensorOffset>2.5</IMarkSensorOffset>
```

기존 JOB 파일은 이번 작업에서 직접 수정하지 않았습니다. 항목이 없는 JOB은 새 코드에서 0으로 읽습니다.
다른 폴더의 실행 파일을 사용하면 그 실행 폴더의 config가 적용됩니다.
